# Pixel preview scenes: composed rows for still screens, `?debug` capture for games

`bun run pixel preview` draws each prototype option into the screen where it appears in the game (`scripts/pixel-scenes.ts`). Screens that are mostly still, like the hub room and the title and menu screens, are composed as rows in the scene. They come from the same generators and timing code the game uses, so no browser is needed. The minigame playfields are mostly moving things (enemies, items, HUD values), and placing those by hand would mean re-creating game state that drifts as the game changes. Their scenes instead write the swapped art through the game's generator to a temporary asset, then capture frames of the real game through the `?debug` hook (ADR 0005). Capture is slower and needs a browser, which is the cost of staying true to the game. A playable preview, with the game running and its art switchable, is not the scene mechanism. It is an extra on each option: `bun run pixel play` (#107) serves the page with a Play link per option, which builds that option in a copy of the working tree and opens the real game.
