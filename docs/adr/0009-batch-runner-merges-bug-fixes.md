# The Sandcastle batch runner merges bug fixes

An exception to ADR 0007. `bun run sandcastle:batch` (sandworm's batch runner, with `batch.mergeBugs` in `.sandcastle/config.ts`) merges a pull request itself, with `gh pr merge --squash`, when all of these hold: the issue is labelled `bug` and `ready-for-agent`, the pipeline's `bun run check` ended green (so the PR is not a draft), and every CI check on the PR passed on the commit being merged (`--match-head-commit`). Bug fixes are small and many, and waiting on a review for each held the queue up; every other PR the batch opens, and everything other agents do, still waits for the owner to merge. Bugs run one at a time, each cut from a freshly fetched `origin/main` after the previous bug merged, so they never conflict with one another. Other work can still land on main while a bug runs, and GitHub runs no CI on a pull request that conflicts with main, so the runner checks for conflicts with a trial `git merge-tree` before it waits for CI and again if CI never starts or times out, and polls GitHub's `mergeable` while it waits. On a conflict an agent merges `origin/main` into the branch (`.sandcastle/sync.md`); once `bun run check` passes the merge is pushed and CI runs again, up to twice. A bug whose check or CI is red, or whose merge GitHub refuses, is left as an open PR for the owner.
